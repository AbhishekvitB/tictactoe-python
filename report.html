2. Introduction

Tic-Tac-Toe is a foundational zero-sum game of perfect information. While standard 3x3 grids permit exhaustive exploration across all 362,880 terminal paths, generalized NxN matrices induce rapid combinatorial expansion (O((N^2)!)). This project delivers an optimized, scalable engine implemented in standard Python that supports variable grid configurations, depth-bounded Minimax search, alpha-beta pruning, and open-line potential heuristics.

3. Problem Statement

Exhaustive Minimax fails on higher dimensions (N ≥ 4) due to combinatorial state space explosion. This project builds a reliable interactive console engine that scales dynamically with sub-second AI turn evaluation, robust move validation, and aligned ASCII rendering.

4. Functional Requirements

  • FR-1: Dynamic scaling to arbitrary N x N dimensions (N ≥ 3).
  • FR-2: Game mode selection with explicit confirmation (Human vs. Human & Human vs. AI).
  • FR-3: Tri-tiered AI difficulty (Easy - Random, Medium - Mixed 50/50, Hard - Alpha-Beta Minimax).
  • FR-4: Coordinate validation preventing boundary overflow and cell collisions.
  • FR-5: Interactive round termination via 'q' / 'quit' command.
  • FR-6: Multi-round session loop allowing continuous replay without script restart.

5. Non-Functional Requirements

  • NFR-1 (Latency): Sub-1.5s AI move generation up to N=7.
  • NFR-2 (Portability): 100% standard library compliance (zero external pip packages).
  • NFR-3 (Visual Usability): Uniform ASCII column centering across multi-column grids.
  • NFR-4 (Memory Footprint): Recursion depth capped at maximum 6 levels.

8. Design Decisions & Rationale

  • Depth Bounds: Depth is capped dynamically (6 for 3x3, 4 for 4x4, 3 for 5x5+) to prevent CPU execution locks while ensuring tactical gameplay.
  • Heuristic Leaf Scoring: When the recursion limit is hit, candidate board states are scored via open-line potential: Score = ∑ 10^(count_O) - ∑ 10^(count_X). Blocked lines (containing both marks) evaluate to 0.
  • Center-Outward Move Ordering: Available moves are sorted by Manhattan distance to the center. Evaluating strong center squares first causes earlier alpha-beta cutoffs, significantly reducing explored nodes.
  • Zero-Dependency Standard Library: Built entirely with native Python modules (math, random, sys) to guarantee native execution on any computer without environment issues.

9. Implementation Details

The code is structured into modular functional blocks:

  • print_board(board): Handles aligned matrix display with 3-character centered cells across any dimension N.
  • check_winner(board): Evaluates all rows, columns, and diagonal lines in O(N^2) time to detect wins or draws.
  • minimax(...): Core recursive alpha-beta tree search with bounded depth exploration.
  • get_human_move(...): Validates inputs, detects out-of-bounds attempts, collisions, and traps 'q' abort signals.
  • play_round() & main(): Oversees mode selection, confirmation gates, and session replay loops.

12. Challenges Faced & Solutions

  • Combinatorial State Explosion: Unbounded minimax search on boards with N ≥ 4 locks CPU execution. Resolved by capping search depth dynamically and scoring non-terminal leaves via an open-line potential heuristic function.
  • ASCII Grid Alignment Drift: Larger matrices previously drifted because column numbers were not padded proportionally. Resolved by standardizing cell widths to 3 characters centered (f" {c} ") with two leading spaces for row indices.
  • Docstring Indentation Error: Inline docstrings immediately following function definitions previously triggered indentation errors. Resolved by placing docstrings within the function block indented with 4 spaces.
  • Interactive Deadlocks: Accidental keypresses previously locked the player into unwanted modes. Resolved by introducing a confirmation gate (y/c) and registering a safe quit command ('q').
